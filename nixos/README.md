# NixOS desktop

NixOS 26.05 with the [Hyprland](https://hypr.land/) compositor with native scrolling and a hand-written [Quickshell](https://quickshell.org) desktop shell, for a Framework Laptop 13 Pro (Intel Core Ultra 5 325). The Graphite look matches the Fedora Graphite profile: a solid black bar, frosted charcoal menus, gray controls, Inter text and light macOS app artwork over a NixOS ASCII wallpaper. The shell is maintained here as QML.

## Layout

| Path | What it holds |
| --- | --- |
| `flake.nix` (repo root) | Inputs (stable nixpkgs and Home Manager, nixos-hardware, Disko) and the two hosts. |
| `hosts/framework/` | The laptop: hardware profile, display, Disko disk layout. |
| `hosts/vm/` | The test VM. |
| `modules/nixos/` | System modules. Hosts only set `desktop.*` options. |
| `modules/nixos/theme.nix` | **The single source for the look**: colours, opacities, radii, spacing, blur, shadows, fonts, wallpaper. |
| `modules/home/hyprland/` | Hyprland's Lua configuration and shortcuts. Settings' choices load from `settings.lua`; HyprMod overrides load last. |
| `modules/home/quickshell/` | The shell's QML. Nix adds `theme.json` and `icons.json` (Lucide names to glyphs). See [Working on the shell](SHELL.md). |
| `modules/home/apps/` | Ghostty, zsh with oh-my-zsh and Starship, development tools, T3 Code, Claude Code, and the btop resource monitor and fastfetch. |
| `assets/nixos-framework.png` | NixOS fetch wallpaper, generated by the ASCII wallpaper project. |

### Options hosts set

| Option | Default | Meaning |
| --- | --- | --- |
| `desktop.enable` | `false` | The Hyprland desktop. |
| `desktop.display.{output,mode,scale}` | any, `preferred`, `1` | The built-in display. |
| `desktop.autoSuspend` | `true` | Suspend after fifteen minutes idle; false in the VNC VM. |
| `desktop.autoLogin` | `true` | Start Hyprland at boot and lock it immediately; the lock screen is the login screen. |
| `desktop.updates.enable` | `false` | Daily automatic upgrades from GitHub. |
| `desktop.dock.pinned` | Ghostty, Zen, T3 Code | Desktop entry IDs always in the dock. |
| `desktop.flatpaks` | Zen, Bitwarden | Flathub apps, installed system-wide and updated daily. |
| `desktop.theme.*` | see `theme.nix` | The look. |

## The shell

| Part | How to open it |
| --- | --- |
| Bar: numbered workspaces, clock, status | Always at the top. |
| Control centre: session buttons, Wi-Fi, Bluetooth, Focus (Do Not Disturb), Airplane Mode, Caffeine, power profile, microphone, colour picker, brightness, volume and now playing, with detail pages for Wi-Fi, Bluetooth, Sound and Now Playing | Click the status pill, or `Super+S`. |
| Notification centre: calendar, selected-day agenda and history | Click the clock. |
| Settings: 19 pages covering desktop preferences, devices, connections, applications and system administration | `Super+,`, search for Settings, or the control center gear. |
| Launcher | `Super+Space`. |
| Clipboard history | `Super+Shift+V`, or the separate clipboard button beside the status pill. |
| Dock | Touch the bottom edge of the screen. |
| Lock screen | At boot, `Super+L`, or the lock button. |
| Volume and brightness pop-ups | The hardware keys. |

Other bindings: `Super+T` terminal, `Super+E` Files, `Super+Q` close, `Super+F` fullscreen, `Super+V` float, `Super+O` overview, `Super+R` cycle column widths, `Super+arrows` focus (with `Shift` to move), `Super+1`–`0` workspaces (with `Shift` to move the column), and `Print` for screenshots. `Super+Shift+/` lists every binding.

Unlocking the lock screen also unlocks GNOME Keyring, which autologin can't do. Without it, apps that store secrets ask for the keyring password.

## Fingerprint unlock

`fprintd` and its PAM integration are installed on both hosts. Enroll a finger on the laptop with `fprintd-enroll`. The lock screen offers **Use fingerprint** only when a reader is available. Password unlock remains available without waiting for a fingerprint scan, and cancelling a scan returns to the password field. PolicyKit prompts can also authenticate with an enrolled finger. The VM has no reader, so only password authentication can be exercised there.

A fingerprint can unlock the desktop but cannot decrypt GNOME Keyring. Enter the account password to unlock stored secrets after boot. The lock screen's password path still unlocks the keyring automatically.

## Settings

Open **Settings** with `Super+,`, the control center's gear, or the app launcher. Search filters sections by their settings, so typing "touchpad", "VPN" or "opacity" finds the relevant page. Volume and brightness have draggable handles, larger targets, keyboard arrows, Page Up/Down, Home/End and wheel input. Clicking the Display or Sound title in the control center opens the corresponding settings page.

Settings has 19 pages. In addition to the original desktop preferences, it now includes accessibility and privacy, in-app Wi-Fi/Bluetooth and per-app audio, Flatpak application management, default apps, startup apps, volumes and Trash, IPP printers and print jobs, time zones and update status/actions. NetworkManager, BlueZ, PipeWire, CUPS, UDisks, GIO, Flatpak and systemd own their respective state. Advanced disk operations, connection-profile editing and account sign-in use maintained native tools.

See [Settings coverage and maintenance](SETTINGS.md) for the full control inventory, remaining gaps, state ownership and validation commands. The interface is shared by the VM and Framework; it does not require maintaining a fork of GNOME or KDE.

Preferences are stored privately under `~/.local/state/system-configs/`. `preferences.json` contains explicit desktop overrides, `settings.lua` and `idle.conf` are generated for Hyprland and hypridle, `displays.json` holds confirmed monitor choices, and `startup.json` holds desktop-entry IDs to launch at login. Changes are validated, written atomically and serialized. Reset preserves monitor choices, applications and accounts. Wallpaper images remain at the selected paths.

The implementation is in `modules/home/settings/`, `modules/home/quickshell/qml/modules/Settings.qml`, `modules/settings/` and `components/settings/`. Nix reproduces the interface, services, native tools and defaults on the Framework. User choices can be transferred with the state files; machine-specific monitor output names can differ. Credentials stay in the keyring. Changing the Nix defaults affects settings without an explicit user override.

The test VM has silent audio devices and no physical backlight, touchpad, Wi-Fi or Bluetooth adapter. Unsupported hardware controls are disabled or labelled. VNC transports the display and input; adjusting the guest's audio volume does not add audio forwarding. Hardware behavior needs testing on the laptop. Authentication dialogs use the installed PolicyKit agent. The test VM's account password remains fixed in its Nix host profile.

Run the settings boundary checks with `nix build --no-link .#checks.x86_64-linux.settings .#checks.x86_64-linux.admin`. They cover invalid input, safe idle timing, failed live changes, persistence across changing defaults, corrupt state, expired previews and display rollback. Both host builds and calendar checks also run in the NixOS workflows.

Run `nix build --no-link .#checks.x86_64-linux.dropdowns` for the Qt Quick dropdown regression tests. They exercise the production control with real pointer and keyboard events, including repeated clicks held beyond the close animation, Reduce Motion, outside dismissal, switching dropdowns and selection. Theme tokens and the motion preference are isolated from the running desktop. The menu excludes its own field from outside-press dismissal so a close click cannot finish the fade before release and reopen it.

The `shellPopups` check runs the production notification popups under a private headless Wayland compositor. It verifies that blur regions follow notification cards when notifications are added, replaced at the same count, removed or cleared. It also checks resizing popup bounds and reopening the launcher after selecting a deeply scrolled app, including rapid reopening and active flick momentum. The settings failure checks also cover switching directly between status-button pages and closing the active page. Both checks run in CI.

## Clipboard history

Use `Super+Shift+V` or the top-bar clipboard button to open searchable history. Arrow keys select an item; Enter or a click copies it back, then use your application's normal Paste shortcut. `Ctrl+D` or the row's × removes one item. Clear asks once before deleting history. Pause stops new captures while saved items remain available; Resume starts capturing again. `Super+V` still toggles floating windows.

Opening history selects the newest entry, including when an asynchronous refresh replaces cached results. Once you navigate with the arrow keys, refreshes preserve your chosen item. Reopening or changing the search resets to the newest matching entry. `nix build --no-link .#checks.x86_64-linux.clipboardSelection` checks delayed loading, navigation, reopening, searching and deletion without reading personal history.

The pinned [cliphist backend](https://github.com/sentriz/cliphist/tree/v0.7.0) handles storage and deduplication. Separate systemd user services capture text and images independently of the desktop shell. The adapter preserves original bytes for recall, restores image MIME types and generates small thumbnails. It keeps up to 200 recent entries, skips selections over 5 MB, and respects application-marked sensitive selections. Data stays in `~/.local/state/system-configs/clipboard/`, with a private directory and database. The pause flag survives login. This is the Linux clipboard; Mac-to-VM clipboard synchronization requires a separate remote-access bridge.

The setup is shared by the VM and Framework in `modules/home/clipboard/`. The popup is `modules/home/quickshell/qml/modules/ClipboardHistory.qml`. Run `nix build --no-link .#checks.x86_64-linux.clipboard` for isolated tests of real cliphist storage, exact text/image recall, deduplication, deletion, pause, sensitive hints and file permissions. These tests never read your personal history.

## Calendars and online accounts

Click the clock to open the calendar. The arrows change the month, clicking a date selects it and loads that day's events, and **Today** returns to the current day. Up to four events appear below the month grid. **Open Calendar** opens the selected date in GNOME Calendar, where you can view the full agenda and create or edit events.

Use **Connect calendars…** to open Online Accounts. Add each account once on each machine, then enable its Calendar service:

| Calendar | Provider to choose | Sign-in |
| --- | --- | --- |
| Google / Google Workspace | Google | Browser sign-in and consent. |
| Outlook / Microsoft 365 | Microsoft 365 | Microsoft browser sign-in. The Exchange/Graph calendar backend is included. |
| Apple iCloud | WebDAV | CalDAV server `https://caldav.icloud.com/`, your Apple Account email, and an app-specific password. |

For iCloud, generate an app-specific password under **Sign-In and Security → App-Specific Passwords** at [account.apple.com](https://account.apple.com/). Apple requires two-factor authentication for these passwords. [Apple's instructions](https://support.apple.com/en-us/102654). The calendar must be stored in iCloud; Mac-only calendars do not synchronize. If WebDAV discovery does not accept the account, Evolution is also installed: use **File → New → Calendar → CalDAV**, enter the same server and app-specific password, and use **Find Calendars**. Calendars added there use the same EDS backend and appear in the widget.

The account window can also be launched with `gnome-online-accounts-gtk`. GNOME Online Accounts and Evolution Data Server synchronize calendars and keep credentials in the login keyring. The widget reads the same selected calendars as GNOME Calendar. Account identities and credentials are configured interactively and are not part of this repository. The reproducible system setup installs the apps, services, provider backends and widget integration. [Supported GNOME account services](https://gnome.pages.gitlab.gnome.org/gnome-online-accounts/services.html).

The GNOME Calendar launcher uses locale-formatted dates and a wrapper pointing at the complete time-zone database. The widget reads EDS's local cache immediately while provider synchronization continues. It refreshes while open, displays errors when a calendar cannot be read, and supports recurring events, all-day events and local time zones. The provider sign-ins and live cloud synchronization require testing with your accounts; no personal accounts are preconfigured in the VM.

## Control center behavior

Power sits directly below Focus. Focus toggles Do Not Disturb. Caffeine attaches a Wayland idle inhibitor only while enabled. The normal idle policy locks after five minutes, turns the display off after six minutes and suspends after fifteen minutes on the laptop. Automatic suspend is disabled in the VNC VM so it stays reachable. Caffeine pauses that policy.

The microphone and volume controls act on the default PipeWire devices. Bluetooth and Airplane are disabled when there are no corresponding radios. Brightness keys and the Display slider act on the focused monitor: the built-in panel's backlight, or an external monitor over DDC/CI through `ddcutil` (users in the `i2c` group can reach it; log out and back in after the first rebuild). A monitor without DDC/CI, or with it turned off in its own menu, falls back to the built-in panel. Plugged-in monitors are picked up a few seconds after they connect. Display brightness is marked **Not adjustable** when the focused output has neither.

### Detail pages

As on macOS, the round icon on the Wi-Fi and Bluetooth pills toggles the radio, and the rest of the pill opens its page. The Sound tile's title and the Now Playing card open theirs. The compact media card centers its artwork or placeholder, title, artist and transport controls, with padding around the whole content group. A page replaces the grid inside the same panel. The back chevron, Esc or the mouse's back button returns to the grid, and Esc again closes the control centre. Notification pop-ups wait while the control centre is open.

- **Wi-Fi:** an on/off switch; Ethernet status; known networks, then others found by a scan that runs only while the page is open, each with signal strength and a lock if secured. Open and known networks join with a click. Others ask for their password inline, and a wrong password shows "Incorrect password" without being saved. Right-click a known network to forget it. Enterprise networks go to Settings.
- **Bluetooth:** an on/off switch; paired devices, which connect or disconnect with a click and show battery levels; nearby devices, found while the page is open, which pair with a click. Right-click a paired device to forget it.
- **Sound:** output and input levels (click the icon to mute), every output and input device to choose from, and a volume for each app that's playing.
- **Now Playing:** large artwork, track details, a scrubber that seeks on release, elapsed and remaining time, shuffle, previous, play/pause, next and repeat, and a picker when several players are open.

The expanded player pads its content by 18 pixels and uses solid black play/pause glyphs on white. It keeps a known duration through incomplete updates for the same track, then resets it when the track or player changes. Playing seeks in Firefox and Zen wait for a brief pause before setting the position and resuming, to avoid [Mozilla's MPRIS timing bug](https://bugzilla.mozilla.org/show_bug.cgi?id=2065930). Paused seeks stay paused; local players seek directly. `nix build --no-link .#checks.x86_64-linux.media` checks the duration-loss replay, consecutive seeks, playback-state preservation, track changes and timeout recovery.

The panel is 381 logical pixels wide, with wider pills and controls and reserved space between each label and its chevron. Hovering an opening pill reveals its chevron without adding an outline or background. Clicking outside or pressing `Super+S` fades the current page out in place; the page unloads only after the panel is hidden, which also stops scanning. Opening the panel again starts at the home grid.

The popup lifecycle regression test runs against the real shell. From a terminal in the desktop session, with Reduce Motion off:

```bash
nix shell .#nixosConfigurations.vm.pkgs.python3 -c python3 nixos/tests/control_center.py
```

It checks that Wi-Fi, Bluetooth and Sound stay intact through closing frames, that hidden pages unload, and that reopening during a fade does not run stale cleanup. `qs ipc call control status` reports the popup and page state for inspection.

## Apps

- **Files and app launchers** use the same pinned Graphite macOS Light app artwork as the Fedora profile, with Papirus-Dark for folders and unmapped apps. Your own images from `icons/` override either theme (see `icons/README.md`). App title bars omit close buttons; use `Super+Q` to close a window. GVfs provides Trash, mounted drives and network locations. Deleted local files can be restored from Trash. The base icon theme is set by `desktop.theme.icons` and `desktop.theme.iconPackage`.
- **GNOME Calendar and Online Accounts** for Google, Microsoft 365 and CalDAV calendars.
- **Ghostty** from nixpkgs, translucent so Hyprland blurs behind it.
- **Zed** from nixpkgs, available in the app launcher and as `zeditor`. The pinned NixOS package updates with the flake.
- **Tailscale** starts its daemon at boot on both hosts. Run `tailscale up` once on each machine to sign in. The desktop user can manage the connection without sudo; credentials stay in Tailscale's local state, outside the repository.
- **Zen and Bitwarden** from Flathub, as on Fedora. Flatpak updates them daily. Bitwarden has the user-authentication PolicyKit action for biometric unlock; enable it in Bitwarden after signing in.
- **Claude Code** through Anthropic's native installer (the latest channel, as on Fedora). A user service installs it once into `~/.local/bin`, and it updates itself from then on. Stable nixpkgs lags it by months.
- **T3 Code**: Nix places the pinned first-install AppImage in `~/applications` once (moving an earlier `~/Applications` copy there), and the app updates itself in place.
- **zsh** with oh-my-zsh, autosuggestions, syntax highlighting, the Starship prompt and the aliases and functions from the Fedora setup. Put machine-only additions in `~/.zshrc.local`.
- Node 24, pnpm, uv, git, vim and make.

Vim and GVim are hidden from the app launcher; Vim remains available in the terminal. The launcher and dock open apps marked `Terminal=true`, such as btop, in Ghostty instead of starting them without a terminal.

The NixOS Manual entry opens the official online manual, since forwarding only its local HTML file into the Flatpak browser loses its stylesheet. System GTK 3 tools use `adw-gtk3-dark`; GTK 4 and libadwaita tools retain their own dark styling. The title-bar layout is `:` with both sides empty, which hides buttons while avoiding a startup crash in Disks 46.

`programs.nix-ld` and AppImage support let these prebuilt vendor binaries run on NixOS.

## Updates

1. Every Monday, the **NixOS update** workflow runs `nix flake update` on the pinned stable release, builds both hosts, and commits `flake.lock` only if they build.
2. The laptop runs `system.autoUpgrade` daily from `github:reiganarmstrong/system-configs`. It builds in the background and applies at the next boot. It never reboots on its own.
3. Each build stays in the boot menu for 14 days; pick an older one to roll back.
4. On the 20th of each month, the **NixOS release upgrade** workflow checks for the next NixOS release. When one exists, it opens a pull request moving to it, which is the one manual step, twice a year. Test the pull request in the VM before merging.

The **NixOS check** workflow builds both hosts on every change under `nixos/` or to the flake.

## Testing in a VM

`nixos-rebuild build-vm` builds a throwaway QEMU VM straight from the flake. The VM renders through the host GPU (virtio-gpu with virgl), which Hyprland uses, and is viewed over VNC on `127.0.0.1:5902`. The VNC password is read at start-up from the file `$VNC_PASSWORD_FILE` names; VNC uses its first eight characters.

On a non-NixOS host, Nix's QEMU looks for GPU drivers in `/run/opengl-driver`, which only NixOS has, so point it at Nix's Mesa. The host user must be in the `kvm` and `render` groups. Log in again after adding group membership. A long-running user service may retain its old groups; launch through `sg kvm -c` in that case, or restart the user session. QEMU falls back to slow CPU emulation when it cannot open `/dev/kvm`.

```bash
nix build .#nixosConfigurations.vm.config.system.build.vm
mesa=$(nix build --no-link --print-out-paths "$(nix eval --raw .#nixosConfigurations.vm.pkgs.mesa.drvPath)^out")
GBM_BACKENDS_PATH=$mesa/lib/gbm \
LIBGL_DRIVERS_PATH=$mesa/lib/dri \
__EGL_VENDOR_LIBRARY_FILENAMES=$mesa/share/glvnd/egl_vendor.d/50_mesa.json \
VNC_PASSWORD_FILE=fedora/.local/vnc-password \
  ./result/bin/run-vm-vm
```

For the existing test disk and VNC password file, `./nixos/run-vm` builds the current configuration and starts it with the required Mesa environment. Shut down the running VM before starting a second instance. Its persistent disk is `.local/nixos-vm.qcow2`.

The VM's password is `nixos`, and SSH from the host works on `127.0.0.1:2222` with the host user's `~/.ssh/id_ed25519.pub`. Its disk, `vm.qcow2`, is created in the current directory; delete it for a fresh first boot.

To view it from another machine on the tailnet, tunnel the port over SSH, then open `vnc://localhost:5902` (on a Mac, in Finder's **Go → Connect to Server**):

```bash
ssh -N -L 5902:127.0.0.1:5902 reagan@pc.taila028da.ts.net
```

### TigerVNC on macOS

The test VM uses 1440×960 at 1× for TigerVNC. It does not automatically suspend; screen locking and display blanking still work. Turn on Caffeine in the control center to keep the desktop visible during a test session.

1. With Tailscale running on the Mac, start the tunnel and leave the terminal open:

   ```bash
   ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 5902:127.0.0.1:5902 reagan@pc.taila028da.ts.net
   ```

2. Open [`clients/TigerVNC-Mac.tigervnc`](clients/TigerVNC-Mac.tigervnc) in TigerVNC Viewer, or enter `127.0.0.1::5902`. The double colon explicitly selects port 5902. The profile enables full screen and system-key capture and keeps the VM's fixed display size.
3. Enter the existing VNC connection password. If the VM is locked, its separate login password is `nixos`.

If macOS keeps the shortcuts, allow TigerVNC under **System Settings → Privacy & Security → Accessibility** and reconnect in full screen. Control+Option releases keyboard capture. [TigerVNC viewer options](https://tigervnc.org/doc/vncviewer.html).

## Installing on the Framework

1. Boot the NixOS 26.05 (or newer) minimal ISO and connect to the network.
2. Check the disk name with `lsblk`, and edit `hosts/framework/disko.nix` if it isn't `/dev/nvme0n1`.
3. Partition, encrypt and mount. This erases the disk and asks for the disk encryption password:

   ```bash
   sudo nix --experimental-features "nix-command flakes" run github:nix-community/disko/latest -- \
     --mode destroy,format,mount --flake github:reiganarmstrong/system-configs#framework
   ```

4. Compare `nixos-generate-config --show-hardware-config --no-filesystems --root /mnt` with `hosts/framework/hardware.nix`, and commit any differences.
5. Install, set your password, and reboot:

   ```bash
   sudo nixos-install --flake github:reiganarmstrong/system-configs#framework --no-root-passwd
   sudo nixos-enter --root /mnt -c 'passwd reagan'
   sudo reboot
   ```

6. For hibernation, find the swap file's offset with `sudo btrfs inspect-internal map-swapfile -r /swap/swapfile`, add `boot.kernelParams = [ "resume_offset=<offset>" ];` to `hosts/framework/hardware.nix`, and push.

After the first boot, the disk password unlocks the machine, Hyprland starts locked, and your account password unlocks it.
